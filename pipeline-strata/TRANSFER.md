# Syncing this tree to the cluster

```bash
rsync -av --delete \
  --exclude '.env' \
  --exclude 'pipeline/samplesheet.csv' \
  --exclude 'src/logs/' \
  --exclude 'work/' --exclude 'results/' --exclude 'analysis/' \
  --exclude '.nextflow*' --exclude '.DS_Store' --exclude '__pycache__/' \
  <local>/pipeline-strata/ \
  user@server:/WHERE/Somalogic/work/GWAS/pipeline-strata/
```

Every exclusion is there because of a specific failure:

| exclusion | why |
|---|---|
| `.env` | Gitignored, so it never travels with the code and has to be edited on the server. Overwriting it from a local copy has twice pointed the pipeline at the wrong genetics directory. |
| `pipeline/samplesheet.csv` | **Generated by `003` on the cluster**, against cluster paths. A local copy is always stale; pushing one silently repoints every study. This happened on 13 Sep and was caught only by the guard in `005_run.sh`. |
| `src/logs/` | With `--delete`, syncing from a machine without logs wipes the run record. |
| `work/`, `results/`, `analysis/` | Large, cluster-side, and regenerable. |

## After syncing

```bash
cd /WHERE/Somalogic/work/GWAS/pipeline-strata
grep -E '^GWAS_(GENETICS_DIR|PHENO_DIR)=' .env      # unchanged by the sync
sbatch src/003_data-phenotype.sh                    # rebuild the samplesheet
grep -E "Loaded .env|Genetics layout|Wrote samplesheet" src/logs/003_data-phenotype.err
```

`005_run.sh` refuses to submit if the samplesheet disagrees with
`GWAS_GENETICS_DIR`, so a stale one fails in a second rather than 27 tasks in.

## Generated artefacts belong only on the cluster

`pipeline/samplesheet.csv`, `data/phenotype-strata/*`, results and work
directories are all built there. Keeping copies locally serves no purpose and
gives `rsync` something wrong to push.
